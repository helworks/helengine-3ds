# Nintendo 3DS textures

The 3DS image and font-atlas cook capabilities publish all fourteen PICA200 texture encodings. Select their IDs in the platform texture override; native assets retain tiled texels or ETC blocks through serialization and GPU upload. The existing `Rgba32`/`A8` default remains available.

| ID | GPU code | Bits/texel | Intrinsic alpha |
| --- | ---: | ---: | --- |
| `Nintendo3Ds.Rgba8` | 0 | 32 | A8 |
| `Nintendo3Ds.Rgb8` | 1 | 24 | Opaque |
| `Nintendo3Ds.Rgba5551` | 2 | 16 | Binary |
| `Nintendo3Ds.Rgb565` | 3 | 16 | Opaque |
| `Nintendo3Ds.Rgba4` | 4 | 16 | A4 |
| `Nintendo3Ds.La8` | 5 | 16 | A8 |
| `Nintendo3Ds.Hilo8` | 6 | 16 | Opaque |
| `Nintendo3Ds.L8` | 7 | 8 | Opaque |
| `Nintendo3Ds.A8` | 8 | 8 | A8 |
| `Nintendo3Ds.La4` | 9 | 8 | A4 |
| `Nintendo3Ds.L4` | 10 | 4 | Opaque |
| `Nintendo3Ds.A4` | 11 | 4 | A4 |
| `Nintendo3Ds.Etc1` | 12 | 4 | Opaque |
| `Nintendo3Ds.Etc1A4` | 13 | 8 | A4 |

Every native ID also accepts `Opaque`, forcing stored alpha to its maximum. Other alpha combinations fail validation. `Hilo8` stores red and green; alpha-only formats decode to zero RGB, matching hardware. The existing citro2d tint path supplies font color.

Authored dimensions can be 1..1024 on each axis. Native storage independently rounds each axis to a power of two with a minimum of eight, repeating border texels into padding. VRAM estimates include this padding and use the selected GPU bit depth. `MaxResolution` is 0 (no resize) or 1..1024; cooking rejects an oversized result. Native payloads currently contain one 2D base level without palettes or mip chains.

## Source import

The editor and builder import `.t3x` files generated by tex3ds in every encoding above. The portable importer accepts uncompressed, LZ10, LZ11, RLE and Huffman streams, including tex3ds automatic compression. It bounds decompression against the complete declared mip allocation and rejects malformed headers, references and nonzero trailing padding.

`Nintendo3DsT3xTextureImporter.ImportTexture(stream)` imports the first subtexture, or the full base level when no subtexture table exists. `ImportTexture(stream, index)` selects another atlas rectangle. Atlas packing rotation is undone. Import returns ordinary RGBA pixels for preview and subsequent cooking; it selects mip zero and does not preserve the source mip chain. Cubemaps are rejected. This importer handles the tex3ds container, not proprietary game containers such as BCLIM/BFLIM.

ETC1 previews decode individual and differential blocks. The cooker produces deterministic individual-mode ETC1 blocks, searching both half-block orientations, nearby quantized averages and all eight modifier tables. ETC1A4 adds explicit four-bit alpha. This encoder favors a small, portable implementation; its lossy color quality can differ from tex3ds's compressor.

## Native asset contract

Shared `TextureAssetColorFormat.Nintendo3DsNative` has wire value 16. `Colors` contains the following eight little-endian 32-bit words, followed immediately by native texels. `PaletteColors` must be absent or empty.

| Byte offset | Value |
| ---: | --- |
| 0 | `0x3154334e` (`N3T1`) |
| 4 | Version 1 |
| 8 | GPU format code, 0..13 |
| 12 | Authored width |
| 16 | Authored height |
| 20 | Padded storage width |
| 24 | Padded storage height |
| 28 | Exact texel byte count |

Component textures use 8-by-8 tiles in row-major tile order and Morton order within each tile. Four-bit texels use the low nibble first. Packed colors use PICA component order, including ABGR bytes for RGBA8 and high red bits for RGB565/RGBA4. ETC blocks follow the four 4-by-4 quadrants of each tile. ETC words are little-endian; ETC1A4's column-major alpha word precedes each color word.

`Nintendo3DsRuntimeTexture` validates the descriptor, allocates the selected `GPU_TEXCOLOR` with citro3d, copies the encoded texels into owned storage and flushes the texture cache. Sprites, font atlases and models share this texture path. Native payloads are not expanded to RGBA during upload.

## Validation

- Checked-in fixtures cover fourteen encodings with six tex3ds compression selections (84 independently generated containers and PNG previews), plus a mip-chain fixture.
- Tests cover native packed words, Morton addresses, ETC differential blocks, malformed descriptors, previews, VRAM estimates, file/runtime serialization, atlas rotation, builder cooking and RomFS staging for images and font atlases.
- Font tests preserve native A8, LA8 and ETC1A4 payloads and coverage through both font readers in both metadata byte orders.
- Actual core-to-C++ generation succeeds. All six new generated codec units and the production descriptor, upload, 2D and 3D units compile with the devkitARM SDK under `-Werror`. The production native descriptor parser passes 182 host checks against managed-cooked fixtures.
- No emulator or physical-device rendering was run. SDK checks compile translation units; they do not claim a linked player or hardware execution.

Validation artifacts are under `builds/helengine-3ds/texture-formats-20261008` in the shared workspace. An expanded existing builder regression run also exposed the unrelated `Makefile_whenPackagingRomFs_accepts_staged_romfs_root` assertion at `Nintendo3DsPlatformAssetBuilderTests.cs:180`; its expected Makefile rule was absent before this change. The Makefile was not modified.
